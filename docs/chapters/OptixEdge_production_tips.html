Limit resource consumption

Set explicit CPU and memory limits so a third-party service cannot starve FactoryTalk Optix or other critical workloads.

services:
  mysql:
    image: mysql:8.4
    deploy:
      resources:
        limits:
          cpus: "0.50"
          memory: "256M"
Confirm how the installed Docker Compose version enforces deploy.resources. Measure actual CPU and memory use on the target device rather than assuming the declared limits are active.

Rotate container logs

services:
  mysql:
    image: mysql:8.4
    logging:
      driver: json-file
      options:
        max-size: "10m"
        max-file: "3"

Pin image versions

Avoid latest in production. Pin a tested version or immutable digest, record the source registry, and define how updates will be approved and rolled back.

Protect credentials

  • Do not commit passwords, tokens, or private keys in compose files.
  • Use the strongest credential mechanism supported by the deployment workflow.
  • Give each service a dedicated account with only the permissions it needs.
  • Rotate tutorial or commissioning credentials before the device enters service.

Reduce network exposure

  • Publish only required ports and bind them to the intended interface where supported.
  • Keep Docker remote management disabled outside controlled maintenance sessions.
  • Place management interfaces behind an authenticated, encrypted access path.
  • Document every open port and the system that is expected to connect to it.

Plan storage, backup, and recovery

  • Store persistent data on media sized for retention and write endurance.
  • Back up named volumes and configuration before upgrades.
  • Test restore procedures on representative hardware.
  • Monitor free space, log growth, database growth, and container restart loops.

Production readiness checklist

  • Image versions and licenses reviewed.
  • CPU, memory, storage, and restart behavior tested under load.
  • Credentials changed and least privilege applied.
  • Published ports documented and restricted.
  • Logs bounded and monitored.
  • Backup, restore, update, and rollback tested.
  • Container failure does not prevent the primary HMI or edge workload from operating safely.
